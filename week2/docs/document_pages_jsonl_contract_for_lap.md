# Document Pages JSONL Contract for Lap

Owner: Duy  
Consumer: Lap - RAG and Embeddings Owner  
Purpose: Define Duy's page-level document output for Lap's chunking, embedding, retrieval, and citation pipeline.

## Why This Contract Exists

Lap's Week 3 RAG module needs page-level text from Duy's document ingestion output. Page-level records are required so Lap can create chunks with stable metadata for citations.

This contract defines the JSONL file that Duy produces:

```text
week2/data/staging/pdf/document_pages.jsonl
```

## Flow

```text
PDF input
  -> Duy PDF ingestion
  -> data/staging/pdf/sample_pdf_text.txt
  -> data/staging/pdf/document_pages.jsonl
  -> Lap document_loader.py
  -> Lap chunker.py
  -> Phat document_chunks table
  -> Phi/Hung chatbot citations
```

## Required JSONL Fields

Each line in `document_pages.jsonl` is one page record.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `document_id` | string | Yes | Stable document ID generated by Duy. |
| `file_name` | string | Yes | Original file name. |
| `page_number` | integer | Yes | 1-based page number. |
| `text` | string | Yes | Extracted page text. Empty string allowed for empty/scanned pages. |
| `character_count` | integer | Yes | Character count of `text`. |
| `is_empty` | boolean | Yes | True if no text was extracted for this page. |
| `source` | string | Yes | Source display name, usually the file name. |
| `raw_output_path` | string | Yes | Project-relative raw file path. |
| `staging_text_path` | string | Yes | Project-relative full extracted text path. |

## Example Record

```json
{
  "document_id": "doc_big_data_engineer2_template_16",
  "file_name": "big-data-engineer2 - Template 16 .pdf",
  "page_number": 1,
  "text": "First Last\nBig Data Engineer...",
  "character_count": 2577,
  "is_empty": false,
  "source": "big-data-engineer2 - Template 16 .pdf",
  "raw_output_path": "data/raw/pdf/sample_pdf_raw.pdf",
  "staging_text_path": "data/staging/pdf/sample_pdf_text.txt"
}
```

## Chunk Metadata Lap Should Preserve

When Lap creates chunks from page records, each chunk should preserve:

```json
{
  "document_id": "doc_big_data_engineer2_template_16",
  "chunk_id": "doc_big_data_engineer2_template_16_page_1_chunk_000",
  "chunk_text": "...",
  "metadata": {
    "file_name": "big-data-engineer2 - Template 16 .pdf",
    "page_number": 1,
    "source": "big-data-engineer2 - Template 16 .pdf",
    "raw_output_path": "data/raw/pdf/sample_pdf_raw.pdf",
    "staging_text_path": "data/staging/pdf/sample_pdf_text.txt"
  }
}
```

## Empty Page Handling

If `is_empty = true`:

- Lap should not create normal semantic chunks from the empty page.
- Lap may create a warning record for retrieval evaluation.
- Phi/Hung can show a parsing limitation.
- Phat can store the page in `document_pages` with `is_empty = true`.

## Database Mapping for Phat

| JSONL field | Database table.column |
| --- | --- |
| `document_id` | `documents.document_id` or mapped to `documents.id` |
| `page_number` | `document_pages.page_number` |
| `text` | `document_pages.page_text` |
| `character_count` | `document_pages.character_count` |
| `is_empty` | `document_pages.is_empty` |

## RAG Requirements Confirmed by Lap

Current MVP assumptions:

| Item | Value |
| --- | --- |
| Embedding model | `sentence-transformers/all-MiniLM-L6-v2` |
| Embedding dimension | `384` |
| pgvector column | `document_chunks.embedding vector(384)` |
| Similarity metric | Cosine distance |
| Citation fields | `file_name`, `page_number`, `chunk_id` |
